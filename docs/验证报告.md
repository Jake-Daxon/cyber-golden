# 赛博金毛 0.3.0 验证报告

日期：2026-10-10，北京时间。环境：Windows NT 10.0.26200 x64（当前 Windows 11），.NET 10.0.12 自包含；构建 SDK 10.0.401。采用上游提交 c3420bb77d6d00ed5fabf975a0945c4f6179bba3。本报告区分源码实现、自动验证、窗口观察和未测试项目。

## 静止陪伴更新

默认使用握手动画第 0 帧的正面形象、双爪落地静坐。三张姿势由 VPet Picture 显示一次并保持，不启动循环；可选择并保存静坐、站立和趴下。普通待机不循环，静止设置关闭随机表演；按最新修正保留独立 CD 的漫游，饥饿提醒作为例外，全部主动动作保留，结束回到所选姿势。关闭漫游时模拟一小时静止、实际图片引用及帧事件停止、三姿势切换、设置保存和独立进程姿势恢复均已加入验证。预览页面默认显示静态图片，点击才播放一次动作。

## 已实现

精简 WPF 宿主确实持有 VPet GameCore、GraphCore、GameSave，使用 PetLoader/GraphInfo/PNGAnimation 载入并播放金毛 PNG。完整原版 Windows 宿主未运行；原始 Core 已在独立 smoke 窗口真实运行。最终运行时不引用 Steamworks、Windows.Interface 或原版角色库。

全部请求功能已有源码路径：BehaviorEngine 的可取消单一状态机和五项 VPet 状态、DesktopPetWindow 的拖拽/菜单/托盘/热键/屏幕边界、Native 的 DPI 与透明轮廓、LocalAudio 的本地声音和限频、ToyWindow 的局部玩具窗口、StateStore 的版本/原子替换/备份/损坏恢复，以及 Inno 安装和卸载脚本。

素材：内置 imagegen 制作五张图集，共 20 组、120 帧；每帧 RGBA 512×512，原生关键帧单元约 256，统一放大整理。同动作统一缩放、脚底定位、透明噪点清理；嘴部锚点按帧存储，低头拾取经过手工坐标复核。GIF/真实尺寸帧条均已输出。声音为授权狗叫派生和原创 Foley，许可/来源明确；不是照片幼犬的真实声线。

## 已自动验证

最终发布 EXE 和安装后的 EXE 均实际启动，不通过 dotnet 命令运行安装版。`verification/publish/results.json` 与 `verification/installed-run/results.json` 各记录 132 项通过，包括：

- 20 组真实 Core 动画加载成功、帧顺序和全部可触发行为的金毛图形回退。
- 主动喂食不被随机/AFK 覆盖、新指令立即替换、拖拽与菜单阻止自主调度。
- 网球和玩偶完整追逐、叼回与清理，低精力缩短距离；隐藏中断追逐并移除玩具、停声、停止位移。
- 睡眠持续、恢复系统输入不强行唤醒、隐藏/恢复仍保持睡眠、叫醒恢复待机。
- AFK 前往安全边缘、趴下并朝向屏幕内部、恢复输入安静退出。
- 加权随机行为的全局冷却和避免连续重复；负坐标显示器及 200% 物理边界算法。
- VPet LPS 存档及稳定标志往返；主档坏则用备份，两个存档均坏则干净默认。
- 实际 RegisterHotKey 冲突、替代快捷键解析、系统最后输入时间戳。
- 静音不创建播放请求、连续点击限频、缺失音频不抛异常。
- 实际 Core 跑动六帧循环；实桌测得帧间隔中位数约 77 ms（以各次 results.json / cadence.json 为准）。
- 动画过程没有成为前台窗口；Windows WindowFromPoint 在透明角落路由至下层窗口，狗身仍保留实际热点。
- 100/125/150/200% 的 WPF 离屏渲染尺寸和清晰 PNG 输出；这不是改变 Windows 系统 DPI 或真实跨屏测试。

`verification/install-results.json` 记录真实 EXE 安装成功、开始菜单已创建、运行时/素材实体存在、安装后 EXE 测试通过、卸载返回 0、应用和开始菜单已移除、默认用户数据保留性标记仍存在。测试后只删除了专门建立的标记，保留用户数据目录。没有执行主动清除用户存档分支。

`verification/restart-results.json` 以七个独立 EXE 进程验证：睡眠直接进入 Sleep，隐藏保持不可见，暂停保持 Idle，普通状态和保存的姿势直接进入所选静止图片；没有从追球或喂食中途重播。

`verification/upstream/upstream-smoke.json`：原始未修改 Core 实际显示了多张不同帧并完成 GameSave 往返。`verification/delivery-audit.json`：逐个检查透明 PNG、音频 PCM、实体文件、ZIP 内容哈希、运行时/原生库和排除项。分发包不含原始照片、参考 PNG、测试存档、Steam、凭据或含开发源码路径的 PDB。

## 未完成的最终验收

1. 资源管理器权限曾被误拒绝，用户随后重新允许访问，并明确确认“功能已经没有问题了”。已记录用户实际验收；代理未完成完整跨窗口拖放自动化，不将用户验收写成代理自动化通过。
2. 本机 WindowsSandbox.exe 不存在，没有无 .NET/Steam 的干净 Windows 10/11 虚拟机测试；自包含结构和本机安装验证不能代替干净机器实测。
2. 当前检查没有完成真实混合 DPI 多显示器切换、拔除屏幕或不同 Windows 10 构建版本实测；仅有算法与离屏 DPI 证据。
3. 透明点击已验证 Windows 命中路由；还没有向不同进程的底层控件注入真实鼠标点击并确认收到事件。没有把“命中路由正确”夸大为全部鼠标环境通过。
4. 20 组动作仍是六个生成关键帧序列。腿、尾、头部和姿态确实运动，但生成素材之间的细微纹理/体型一致性、全部姿态衔接及睡眠胸腹呼吸的最终自然观感仍需逐动作人工复核；没有声称达到逐帧手工动画的最终品质。
5. 声音接口、静音、限频和容错已验证；自然幼犬音色、听感和设备不可用时的实际硬件故障尚未人工试听/实测。
6. 安装的默认保留、开始菜单和卸载已验证；桌面快捷方式选中分支、交互卸载主动清档分支和登录后自启动需专门实机验收。测试未修改系统 DPI 或启用 Windows 可选组件。

已发现并解决：图集间距不齐引起裁切/邻帧残片；动画文件未保证顺序；旧播放回调可能越过取消；透明轮廓提交过多 API 调用；测试预览继承欢迎目标导致提前回待机、误测成 600 ms 帧速；素材更新仍复用旧缓存。原始失败日志保留用于追溯，不替代最终通过结果。

结论：首个可运行、可安装、可私下分享的版本及源码/脚本已形成；以上未完成验收项明确保留，不能将该版本称为全部最终验收通过。
